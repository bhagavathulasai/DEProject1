# DentalVision AI — Setup and Handoff Guide

This guide describes the **current FastAPI application** in this repository.
It replaces the older Flask-oriented instructions: `python app.py` starts
FastAPI on port `8000`, not a Flask website on port `5000`.

The project is an educational prototype for dental/oral-image classification.
It is **not a medical diagnostic tool**. The currently available smoke-test
model loads, but its saved evaluation reports only 20% accuracy on 20 test
images. Do not rely on its predictions for health decisions.

## 1. What a new user needs

### Required to start the API

- This repository cloned from GitHub.
- Python 3.11 and pip, or Docker Desktop with Docker Compose.
- A local `.env` file containing a valid `GROQ_API_KEY` for image validation.
- A trained model file if the user wants predictions to run successfully.

The repository currently tracks the dataset under `Data set/`, so it is
included in a normal clone. At the time this guide was updated, it contained
6,677 image files (about 0.17 GiB); the count and size can change.

The trained model is **not included in Git**. The current model is about 298 MiB
and is ignored by Git because model artifacts are large. To run predictions, a
project owner must securely provide the model file separately, or the new user
must train a model themselves (see section 7). The owner should share the
specific model file through an approved file-sharing method, not by committing
it to GitHub.

### Required only for training

- The dataset folders under `Data set/` (currently tracked in the repository).
- Additional disk space and time for TensorFlow training.
- A Python environment with the dependencies in `requirements.txt`.

PostgreSQL is started by Docker Compose but is optional when running locally:
the API can start without it. Prediction history is currently kept in memory,
not in PostgreSQL.

## 2. Get the code

Clone the GitHub repository and move into its project root (the folder
containing `app.py`):

```powershell
git clone <repository-url>
cd <repository-folder>
```

Do not download only `app.py`; the application needs the Python packages,
`api_app/`, `dentalvision/`, and configuration files from the repository.

## 3. Configure local environment

Create a local `.env` from the safe template:

```powershell
Copy-Item .env.example .env
```

Edit `.env` and set your own Groq API key. Never send the `.env` file to
friends, commit it, or paste its contents into chat or documentation. Each
developer should create their own local `.env`.

The local Python app reads these settings:

| Variable | Purpose |
|---|---|
| `GROQ_API_KEY` | Required to send uploaded images for the external image-type validation. |
| `DENTALVISION_MODEL_PATH` | Optional path to a particular `.keras` or `.h5` model file. Leave blank to use the standard model search. |
| `DENTALVISION_MODEL_DIR` | Model fallback directory; defaults to `./models`. |
| `DENTALVISION_DATASET_DIR` | Dataset location; defaults to `./Data set`. Needed for training, not normal inference. |
| `DENTALVISION_UPLOAD_DIR` | Upload storage directory; defaults to `./storage/uploads`. |
| `DENTALVISION_STORAGE_DIR` | Reserved secure-storage path; defaults to `./storage/secure`. |
| `DATABASE_URL` | PostgreSQL connection. Local startup can continue if PostgreSQL is unavailable. |
| `PORT` | API port; defaults to `8000`. |

Use paths relative to the project root (for example
`DENTALVISION_DATASET_DIR=./Data set`) or an absolute path for local Python.
Run `python app.py` from the project root so relative paths resolve as expected.
Do not copy a developer's absolute Windows paths to another computer.

### Add the model file

For the API to make predictions, place the provided model at:

```text
models/Improved_CNN_trained.keras
```

Create `models/` if it does not exist. In `.env`, either leave
`DENTALVISION_MODEL_PATH` blank and use a supported fallback filename, or set
it to the actual model path. The current model generated by the training
pipeline is named `Improved_CNN_trained.keras`, so the simple option is to set:

```env
DENTALVISION_MODEL_PATH=./models/Improved_CNN_trained.keras
```

This is a Keras model artifact, not source code. Do not rename an unrelated
file to this name; the content must be a model saved in a compatible format.
If the model is absent or cannot load, the API can still start, but prediction
requests will not succeed.

## 4. Run locally with Python (recommended first run)

Use Python 3.11. From the project root in PowerShell:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

Start the application:

```powershell
python app.py
```

Keep the terminal open while using the API. Open:

- Interactive API and image upload: <http://localhost:8000/docs>
- Health status: <http://localhost:8000/api/v1/health>
- Alternate API documentation: <http://localhost:8000/redoc>

The root URL `http://localhost:8000/` is not the old Flask upload page. To
make a prediction, open `/docs`, expand `POST /api/v1/predictions`, select
**Try it out**, choose an image, and execute the request. Supported formats
are PNG, JPG/JPEG, BMP, and WEBP. The default upload size limit is 8 MB.

The request sends the image to Groq for an image-type check. Do not submit
identifiable patient images unless you have authorization and have reviewed
the applicable privacy requirements.

In another PowerShell window, check the API:

```powershell
Invoke-RestMethod http://localhost:8000/api/v1/health
```

Expected output includes `status: ok`, `model_loaded`, and `groq_configured`.
`model_loaded` should be `true` before attempting a prediction. If it is
`false`, check the model path and startup logs.

### Stop the local server

Return to the terminal running `python app.py` and press **Ctrl+C**. The API
uses port 8000; stop it before starting Docker Compose on the same port.

## 5. Run with Docker Compose

Install and start Docker Desktop first, then open a PowerShell terminal in the
project root. Create `.env` and add a valid `GROQ_API_KEY` as described above.
Place the trained model at `models/Improved_CNN_trained.keras`.

Build and start both the API and PostgreSQL:

```powershell
docker compose up --build
```

Wait for the database health check and API startup. Then open:

- API documentation: <http://localhost:8000/docs>
- Health status: <http://localhost:8000/api/v1/health>

Compose maps the API to host port `8000` and PostgreSQL to `5432`. The Compose
configuration mounts `./models` into the container and sets the container
model path to `/app/models/Improved_CNN_trained.keras`. Therefore, the model
must have that filename and be present in the local `models/` folder before
starting Compose. If using a differently named model, update the Compose
`DENTALVISION_MODEL_PATH` to the matching container path.

If you already have the current smoke model under
`artifacts\smoke\models`, you can copy it into the expected Docker location:

```powershell
New-Item -ItemType Directory -Force .\models
Copy-Item .\artifacts\smoke\models\Improved_CNN_trained.keras .\models\Improved_CNN_trained.keras
```

The model copy is ignored by Git and remains local.

To run in the background:

```powershell
docker compose up --build -d
docker compose ps
docker compose logs -f api
```

Stop the containers with:

```powershell
docker compose down
```

This keeps the named PostgreSQL data volume. Do not add `-v` unless you
intentionally want to delete that database volume and its data.

### Docker troubleshooting

- **Port already allocated:** stop the local `python app.py` process or the
  other container already using port 8000; do not run both servers on the
  same port.
- **Model missing in container:** confirm
  `models/Improved_CNN_trained.keras` exists on the host and restart Compose.
- **Groq validation fails:** confirm the local `.env` has a valid key and
  restart/recreate the API container after changing it.
- **Database warning locally:** Docker Compose starts PostgreSQL automatically.
  When running Python directly, PostgreSQL is optional for API startup; a
  warning that table creation was skipped is not the same as API startup
  failure.

## 6. Use the API

| Method and route | Use |
|---|---|
| `GET /api/v1/health` | Check API, model, and Groq configuration status. |
| `GET /api/v1/models` | Check the model name and load status. |
| `POST /api/v1/predictions` | Upload an image and request a prediction. |
| `GET /api/v1/predictions` | List predictions kept by the current process. |
| `GET /api/v1/predictions/{prediction_id}` | Retrieve a prediction from the current process. |

The prediction-list endpoints use an in-memory store. Records disappear after
the API restarts; the database tables currently present in the code are
scaffolding and are not yet used to persist prediction results.

## 7. Train a model instead of receiving one

The training pipeline uses the dataset folders in `Data set/`. It can train
`Improved_CNN`, `MobileNet`, `ResNet50`, or `EfficientNetB0`. Training can be
computationally expensive; the native Windows TensorFlow installation used by
this project runs on CPU.

From the project root:

```powershell
python train_pipeline.py --help
python train_pipeline.py --dataset-dir "Data set" --output-dir artifacts\experiment --model-name Improved_CNN
```

The generated model is written under:

```text
artifacts/experiment/models/Improved_CNN_trained.keras
```

Evaluation metrics and Grad-CAM files are written alongside it. To use it
locally, set `DENTALVISION_MODEL_PATH` in `.env` to that file path. For Docker,
copy the selected artifact into `models/Improved_CNN_trained.keras`, or update
the Compose model path and mount to match.

Training a model does not demonstrate that it is accurate. Evaluate it on a
large independent test set and review per-class metrics and the confusion
matrix before interpreting its outputs.

## 8. What to send a friend / what GitHub should contain

### Commit/push the project source

The GitHub repository should contain the source code and configuration
templates needed to build the app, including:

- `app.py`, `api_app/`, `dentalvision/`, `another.py`, `project_config.py`,
  and `train_pipeline.py`.
- `requirements.txt`, `requirements-dev.txt`, `pyproject.toml`, `Dockerfile`,
  `docker-compose.yml`, and `.dockerignore`.
- `.env.example` with placeholders only; never a real API key.
- `Data set/` if you have permission to share the dataset and are willing to
  host its size in the repository. It is currently tracked in this checkout.
- Tests, migration files, frontend source, and documentation as needed.

Before sharing, check the GitHub repository's access level, dataset license,
and whether any uploaded images contain personal or patient information.

### Provide separately (or generate locally)

- **A Groq API key:** each user should create or obtain their own key and add
  it to their own untracked `.env`. Never share your personal `.env`.
- **A trained model:** supply the `.keras` model separately (about 298 MiB for
  the current smoke model), or have the user train their own. The model is not
  tracked by Git because model extensions are ignored.
- **Python/Docker software:** the friend installs Python 3.11 for local
  execution, or Docker Desktop for Compose. These are installed on their
  computer, not copied from this repository.
- **Dataset, if removed from GitHub:** distribute it separately only if its
  license and privacy terms permit. Otherwise the friend needs an authorized
  dataset source to train a model; they can still run the API without the
  dataset if they already have a compatible model.

### Local/generated items that should not be sent or committed

- `.env` and any other file containing credentials.
- `.venv/`, Python caches, `.pytest_cache/`, `.ruff_cache/`.
- Model binaries such as `.keras` and `.h5`, unless deliberately shared
  outside GitHub.
- Uploaded images and contents of `static/uploads/`, `storage/uploads/`, and
  `uploads/`.
- `frontend/node_modules/` and generated `frontend/dist/`.
- PostgreSQL container data/volumes and local logs.

### Important Git/security cleanup for this checkout

This checkout previously tracked `.env` and uploaded images. They have now been
removed from the Git index while retaining the local files, and `.gitignore`
prevents them from being re-added. Include these staged removals and the
`.gitignore` change in the next commit so new clones no longer receive them.
Check the GitHub repository after pushing.

Removing a file in a new commit does not erase it from earlier Git history. If
the Groq key was ever pushed or exposed, revoke/rotate it immediately. Treat
any uploaded images that may contain personal or patient information as
sensitive; if they were pushed, follow the repository owner's privacy and
history-removal process. Coordinate any history rewrite with collaborators
before attempting one.

## 9. Current limitations

- This is an academic prototype, not a clinical diagnostic tool.
- The current smoke model's recorded evaluation is weak (20% accuracy on 20
  test images); it should only be used to verify that the loading and API
  workflow functions.
- Prediction uploads are sent to Groq for validation.
- The React frontend is an experiment and is not connected to the API;
  `/docs` is the current way to test image uploads.
- Prediction history is in memory; PostgreSQL persistence is not implemented
  in the active prediction flow.
- `legacy_flask_app.py` and `templates/index.html` are an older Flask
  prototype. They are not launched by `python app.py`.
- Historical project documents may describe port 5000 or claim no model is
  present. Use this guide for the current FastAPI application and verify the
  local model file independently.
